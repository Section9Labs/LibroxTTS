# Existing Librox iCloud library

This follow-up replaces the companion's import-only entry point with the user's existing Librox library.

The installed main Librox app is signed for Production iCloud. The companion's existing development provisioning profile permits both Production and Development, so the companion build now defaults to Production. Library discovery starts independently of enabling inference. It reads `CD_StoredBook` metadata and incremental changes from the existing private SwiftData zone without writing those records or changing reading progress. The new `ChatterboxCloudLibrary` service lives in the portable planning product.

The signed live check found **51 books**, including **32 with last-opened activity**. It downloaded an original EPUB, verified its synced SHA-256, and imported **15 original spine entries** from **189,249 bytes**. No model loaded during this check. An earlier first-book check exceeded the import limits; that attempt is not counted as a successful import. Oversize books receive an explicit error rather than truncation.

The panel shows titles/authors, synced last-opened dates and progress, recent-first ordering, search, and a prepare action. Selections are stored durably and account-bound. Requests from other Librox clients are discovered without loading the model; their UI is labeled "Requested in Librox" because the request protocol does not establish a platform name. The library likewise has no last-opening-device field, so neither iPhone nor Mac origin is fabricated.

The initial Production narration schema probe failed because the catalog type did not exist. The user signed in to CloudKit Console and deployed the pending changes. A subsequent Production schema export verified all ten required record types and all required fields (`production-schema-2026-11-05.json`). Per-book failure status now uses the already-deployed directory metadata record type under its own validated key. No separate failure record type or further schema deployment is needed. The companion recognizes the query-index-only error as schema present because the actual narration protocol fetches records by ID.

Focused regression verification passed **13 tests** across library projection, operation cancellation/join ownership, exact source/export preservation, EPUB/Unicode import, native claim/control fencing, and concurrent publication reads. Reads retry a complete strict snapshot at most four times when publication advances it; account/intent revocation and persistent validation failures still fail. Writes retain their existing conditional transaction policy.

The first Production audio run reached three verified downloads, then a concurrent snapshot change surfaced as a reader conflict; it joined and exited without claiming a pass. This prompted the bounded read recovery and its tests. The subsequent run used changed self-authored text and a fresh scope and **passed in 362.4 seconds**: real native synthesis, Production publication, all **four verified reader downloads** across both chapters, verified end-of-book completion, and joined shutdown. It used explicit ALAC24 and did not reuse the first run's completed audio. The receipt is `delivery-production-2026-11-05.json`; the exact installed executable identity and signing check are in `installed-library-build-2026-11-05.json`.

Remaining scope: the main iOS/macOS reader must still integrate the concrete preparation service to submit its own narration requests and play verified audio. Its existing book imports and reading activity already appear in the companion through the current library schema. EPUB extraction identities remain explicit; main-reader source offsets must not be reused for companion-extracted text without a shared exact extraction contract. Physical iPhone playback and listening acceptance are not established by these checks.

The mapping follows Apple's documented [Core Data CloudKit record layout](https://developer.apple.com/documentation/CoreData/reading-cloudkit-records-for-core-data). Metadata-only fetches use [`desiredKeys`](https://developer.apple.com/documentation/cloudkit/ckfetchrecordzonechangesoperation/zoneconfiguration/desiredkeys), with original files downloaded only on selection.

The installed Production-signed app was visually inspected with the real library in light and dark appearance. All 51 books appeared, with recently opened titles first; searching for Alice narrowed the list correctly. The initial SwiftUI scrolling area collapsed after asynchronous load and was corrected with a stable bounded viewport before installation.
