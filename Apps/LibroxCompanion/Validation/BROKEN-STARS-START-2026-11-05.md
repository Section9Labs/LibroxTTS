# Broken Stars preparation started

The installed companion successfully downloaded Broken Stars from the existing Production library, admitted all 63 narration parts, uploaded all 63 source contents, confirmed the wanted request, and began actual native synthesis. The UI reported “Preparing audiobook · Broken Stars · Chapter 2 of 63 · 1 audio parts sent.” The first verified artifact is AAC-LC, 24 kHz mono, 287,040 decoded frames (11.96 seconds), with a file hash matching its segment manifest. The callback updates the sent count only after the segment asset upload and fenced head append succeed. Preparation was left running; this is start/publication evidence, not whole-book completion or listening acceptance.

The blocking CloudKit failure was reproduced in the old installed app. Its record-zone request used utility QoS, inferred discretionary scheduling, 15-second request / 30-second resource timeouts, and recorded zero bytes sent with no connection established before timeout. The Mac could reach Apple's service, and other native CloudKit clients completed requests. The shared native operation wrapper now explicitly uses user-initiated QoS and bounded 60/120-second deadlines. After installing it, all 51 library books loaded and actual source/audio publication succeeded. Post-fix native logs confirm the new configuration. No account reset, schema change, data deletion, or unrelated process termination was used.

The original companion process was stopped for replacement after native UI control repeatedly timed out; it had not started a book preparation. The new app was operated through native UI: selected Broken Stars, then used Try Again once to clear a transient storage-busy error while the durable source upload continued. Six importer tests from the preceding revision remain historical; this scheduling-only follow-up was validated with the signed Release build, strict signature verification, real iCloud request confirmation, and the first actual AAC publication. Cancellation/join and transaction fencing code are unchanged.

Apple documents utility CloudKit requests becoming discretionary while an app is inactive in its [QoS guidance](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/EnergyGuide-iOS/PrioritizeWorkWithQoS.html). The verified local observations above establish the recovery for this app.
