# Durable local chapter options

`ChatterboxLocalRenderPlan` in the Reader-safe `LibroxChatterboxPlanning` product publishes the already validated portable render plan as an immutable, account/source/request-bound local record. It reuses the SDK's bounded immutable filesystem helper through package-only access; applications cannot use that helper or construct successful publication receipts themselves.

Publication requires the exact `ChapterSubmission`, the SDK-created source publication and the Reader's current session gate. The record binds the canonical render key, account partition, exact source content reference and canonical plan bytes. The plan retains every authored expression range/control bit, direction, grouping, explicit delivery and UInt64 seed. It does not serialize a path, epoch, file handle, private conditioning or a borrowed credential. The envelope is bounded to four MiB, including the plan's base64 encoding; the inner plan retains its two-MiB bound and all original source/annotation limits.

Before publication and after receipt the SDK checks source bytes, language, delivery, expression digest, fixed seed policy and the complete canonical synthesis-options fingerprint against the expected request. This includes grouping and direction even when a completed encoded artifact is reused without loading a model. Six legacy fingerprints were frozen before sharing that calculation and remain unchanged. Actual resident model/conditioning/backend qualification still precedes new inference. A hash cannot supply missing settings and a stored plan must never trigger work by itself.

The file operation uses an owned utility task, descriptor-bound staging, actual staged readback, read-only permissions, no-replace publication, exact existing-record reconciliation and parent synchronization. Cancellation signals and joins the owned operation. A late cancellation or account revocation may leave a complete immutable file, while returning no successful publication. Unknown files and original source assets remain untouched. Aggregate retention/quota and orphan collection are separate, unfinished service requirements.

`ChapterDemandOutbox.setDemand(_:for:source:renderPlan:)` atomically stores the pending intent, source reference and matching plan reference in one Reader-owned journal snapshot. Attaching the plan to an older wanted intent advances its revision and invalidates older acknowledgements. Cancel/re-request preserves completed source/plan references. It does not mark server acceptance or playable audio. `storedSubmission(for:)` returns the optional plan reference alongside the existing source/intent metadata.

The first plan reference writes explicit journal V4. V1, V2 and V3 encodings remain unchanged when no plan exists; old writers reject V4 rather than strip options. V4 entries without source references are corrupt. Only temporary validation journals have been used; no user data migration has occurred.

The receiver first re-admits exact source under its own current session, then calls `ChatterboxLocalRenderPlan.receive`. It checks immutable record hash, canonical metadata, account/render/source identity and every portable option constraint before returning exact options. The producer epoch is absent. Receiving options is neither a current-wanted observation nor a worker claim.

Authoritative immutable Reader intent publication, generation/claim fencing, Worker checkpoints, service/catalog orchestration and real host/cloud integration are still required. The application factory remains unavailable until a reviewed committed dependency and separate runtime authority exist. Local filesystem/fake-backend tests do not establish model quality, speed, cross-process signing, power-loss behavior or cloud delivery.
