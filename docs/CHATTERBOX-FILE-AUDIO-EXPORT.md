# Bounded local chapter encoding

`NativeFileAudioExport` is the file-backed codec/readback component for the upcoming resident Mac renderer. It does not construct a model, render text, provide a `ChapterService`, or publish CloudKit records. The existing 120-second array exporter is unchanged.

The input contract is a private producer-owned, regular file containing exact little-endian Float32 mono PCM at 24 kHz, its exact frame count, and its lowercase SHA-256. A future renderer must finish and fence that spool before encoding. Each encode opens the input without following its final symlink, checks descriptor/path identity and size, hashes it during both encoding and readback comparison, and checks its identity again before publication. A FIFO is rejected without waiting for a writer. No input is moved or deleted.

The new scope admits at most six hours / 518,400,000 frames and one GiB of encoded output. Processing uses 65,536-frame chunks. The output budget is checked after each encoder write and before publication; AVFoundation may buffer or write a chunk before the check, so it is not a guarantee that the opaque encoder never transiently writes more than the limit. No over-budget output is published. Cancellation and low-power/thermal checks occur between bounded reads, writes, and readback work. The synchronous API belongs on an owned off-main worker; its caller must cancel and join that worker before releasing custody.

Codecs are AAC-LC requested 64 kb/s, ALAC24, WAV Float32, and WAV PCM16. All outputs are reopened and decoded: actual codec, mono/24 kHz, exact gapless frame count, finite samples and full scale are required. Float32/PCM16/ALAC are also compared to the original PCM at their existing precision bounds. AAC reports measured error and does **not** claim sample equivalence or listening approval.

Encoding happens in a new mode-0700 UUID child of an existing private app-owned output directory. After verification, the file becomes read-only and a hard link publishes it atomically without replacing any existing destination. File and directory synchronization must succeed before a receipt is returned. The destination and staging directory must be on the same filesystem. The containing directory is an application custody boundary with one writer; this API does not promise protection against an adversarial same-user process racing AVFoundation's path-based APIs or modifying ancestor paths.

Cleanup removes only a matching, descriptor-bound staging file and the matching empty staging directory. It never recursively deletes a directory. Unbound encoder-construction leftovers or unknown entries are preserved for explicit recovery. A cancellation or storage failure **after** the final link may leave a complete output without a returned receipt. Callers must reconcile and verify such output; neither a thrown error nor a missing receipt authorizes deleting it or claiming that nothing was written.

Synthetic Release tests cover a 3,100,001-frame AAC/ALAC export beyond the old 120-second bound, exact gapless decoding, WAV precision, malformed PCM/hash/frame admission, symlink/FIFO rejection, source replacement, cancellation, unknown-file preservation, a destination created during encoding, and late cancellation after publication. These are codec/custody checks, not full-chapter model inference, a resident renderer, source-frame-map continuity, production host acceptance, cloud transfer, voice-quality approval, or throughput proof.
