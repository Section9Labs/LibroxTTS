# Local Worker generations and Reader acceptance

`ChapterWorkerJournal` is a private, account/Worker-scoped local state store. Its lifetime filesystem lock permits one owner of that journal. It does not open the Reader's outbox, use wall-clock lease expiry, replace CloudKit transactions or coordinate workers that were configured with different private stores. The future service must provide the qualified Worker/State root and retain the journal until all producers have joined.

Claims start disabled. An enabled claim checks the exact Reader read set through the supplied current authority, persists a monotonically increasing generation, then checks current authority and cancellation again before returning a token. The token includes a fresh process-run UUID and is not Codable. The journal retains the claim's original Worker account session privately; an old token cannot borrow a new same-account epoch. A new epoch requires stopping/joining the old generation and acquiring a new one. No account epoch is serialized in portable state.

Only one generation may be active. An operation slot prevents actor reentrancy from creating overlapping claims or changing a claim during an authority await. Disabling new claims remains available during those awaits. Each work/progress/publication admission checks the token, current Reader intent, Worker session and applicable enabled state. These checks are observations; they do not freeze the Reader's intent for the duration of rendering.

Measured unit progress is bounded and monotonic. It is not a model KV checkpoint or evidence that partial audio can resume. Publication stores an intended content reference before file transfer. The new `ChapterLocalHandoff.publishVerified` returns an SDK-created, live-process completion receipt only after the existing complete copy/hash/canonical metadata publication and owned file task finish. A Worker publication checkpoint records this physical evidence; it does **not** mark Reader audio ready or acknowledge demand.

Physical publication does not prove that every producer has joined. Even a `.published` generation stays active and retains exclusive ownership until the orchestrator explicitly cancels/joins all outstanding work and calls `relinquishAfterJoining` or `closeAfterJoining`. Normal `close` refuses active work. These methods encode a caller obligation; this journal component does not own the renderer task chain yet. The actual service must enforce the join, including preparation and codec tasks.

Reopen uses a new run UUID and converts incomplete rendering/publication records to interrupted checkpoints before exposing the journal. Source/plan identities, measured progress, completed publication references and an explicitly unverified recovery-candidate reference survive. A lost publication callback therefore does not lose its lookup key on the next claim. Any candidate must still pass actual complete receive/copy/decode and current-source/session validation; a reference is never playable by itself. Failure records require a new explicit Reader intent before another attempt at the same failed request.

The checked canonical journal is limited to 8,192 records and 32 MiB. An immutable, role/account/Worker-bound initialization marker is synchronized before a fresh journal can become usable. Missing established journals, invalid roles/checksums, impossible counters or corrupt records fail closed instead of restarting at generation zero. Interrupted initialization remains explicit. Writes use owned staging, actual readback, file/parent synchronization, atomic replacement and inode-bound staging cleanup. An ambiguous commit poisons the handle; after producers join, close without guessing the result and reopen to reconcile the checked journal. Unknown files, original audio and prior completed publications are preserved.

Reader acceptance is separate. After actual `ChapterLocalHandoff.receive` has privately copied and decoded complete audio under the Reader's own current session, `ChapterDemandOutbox.acceptVerifiedHandoff` checks exact source, request, current wanted intent and both content references. Its current-intent comparison and handoff-reference journal update have no intervening await. It then checks account/cancellation/current intent again before returning `ChapterReaderArtifactAcceptance` with verified custody. A late cancellation returns no stale accepted artifact, while preserving a completed reference already committed for the old revision. Server acknowledgement/pending demand are unchanged. An explicit fresh demand may re-adopt the same verified complete content; an old callback cannot accept itself into that revision.

The acceptance value records a past atomic local decision, not an indefinite playback grant. The host must still fence UI callbacks and playback by its own current account/session/request. Worker `.published` state and a complete file alone never activate Reader availability.

Validation uses synthetic exact source and references, fake producer state and real small WAV custody/publication/readback. It covers default-disable, one active claim, progress bounds, disable/cancel during awaits, process-run/generation/epoch fencing, join-before-release, publication versus acceptance, lost-callback recovery, missing/corrupt established state, role locks and ambiguous-write reopen. No model inference, full narration, actual process crash/power loss, signed host, App Group, cloud or throughput qualification is implied.

The resident-renderer task orchestrator, actual cancellation/join lifecycle, aggregate quota/retention, concrete local service/catalog/factory and signed real-generation acceptance remain required. The app backend stays unavailable on its frozen dependency until those gates and committed SDK delivery are complete. Distributed cloud claims and clock uncertainty remain a later protocol.
